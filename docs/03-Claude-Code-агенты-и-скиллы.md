# Настройка Claude Code для разработки «Фабрика Снов»

Этот файл — не часть игрового дизайна, а план того, как организовать работу с Claude Code при реализации проекта из файлов 01 и 02.

## 1. Общая схема работы

Claude Code — это агент, работающий с файлами в репозитории через терминал. Roblox Studio сам по себе не читает файлы с диска, поэтому нужен мост:

**Roblox Studio ⇄ Rojo ⇄ Git-репозиторий ⇄ Claude Code**

- Весь Luau-код пишется как обычные `.luau`-файлы в структуре из ТЗ (раздел 3).
- **Rojo** синхронизирует эти файлы в открытый проект Roblox Studio в реальном времени (плагин Rojo в Studio + `rojo serve` в терминале).
- Claude Code пишет/редактирует эти файлы напрямую, коммитит в git — стандартный для него режим работы, ничем не отличается от обычного software-проекта.
- Тестировать геймплей всё равно приходится вручную в Studio (плейтест), либо через MCP-мост, описанный ниже в п. 4, который даёт Claude Code возможность действовать внутри самого редактора Studio, а не только редактировать файлы на диске.

Рекомендуемый первый шаг в самом Claude Code: попросить его инициализировать `default.project.json` под структуру из ТЗ и настроить `rojo` как dev-зависимость проекта.

## 2. Кастомные субагенты (`.claude/agents/`)

Субагенты в Claude Code — это md-файлы с YAML frontmatter (`name`, `description`, `tools`, опционально `model`), которые живут в `.claude/agents/` (для проекта) или `~/.claude/agents/` (глобально). Проще всего не писать их руками, а прямо в Claude Code попросить: «создай субагента с такими-то ролью/инструментами/системным промптом» — Claude Code сам сгенерирует корректный файл. Ниже — какие роли имеет смысл завести под этот проект.

| Субагент | Зона ответственности | Когда делегировать |
|---|---|---|
| `lua-systems-engineer` | Реализация серверных систем из ТЗ (CollectionSystem, FactorySystem, PetSystem и т.д.) на Luau, строго по контрактам из `Types.luau` | Основная разработка игровой логики |
| `economy-balancer` | Расчёт и калибровка кривых цен, шансов петов, формул rebirth-множителя; работает с числами и таблицами, а не с UI | Балансировка экономики, генерация/правка `Config/*.luau` |
| `security-reviewer` | Ревью на серверную авторитетность: ищет места, где клиенту доверяют данные, которые должен считать сервер | После написания каждой новой RemoteEvent-цепочки |
| `qa-test-writer` | Пишет чек-листы и, где возможно, юнит-тесты для чистых модулей экономики (без Instance-зависимостей) | Перед мержем фичи / перед этапами из ТЗ (MVP, Alpha, Beta) |
| `ui-luau-dev` | Клиентский UI (HUD, ShopUI, ChaosEventUI) на Luau/Roact-подобных паттернах | Работа над интерфейсами |

Для каждого стоит явно ограничить `tools` (например, `economy-balancer` не нужен доступ на запись в UI-папки) — это снижает риск, что один агент случайно правит чужую зону ответственности, и держит контекст каждого сфокусированным.

## 3. Project-level инструкция (`CLAUDE.md`)

Помимо субагентов, стоит завести в корне репозитория `CLAUDE.md` с выжимкой из архитектурных принципов ТЗ (раздел 2): «сервер всегда авторитетен», «конфиги отдельно от логики», структура папок, соглашения об именовании. Claude Code читает этот файл автоматически в начале каждой сессии — это дешёвый способ не повторять архитектурные ограничения в каждом запросе.

## 4. MCP-серверы (мост в саму Roblox Studio)

Помимо чтения/записи файлов, для полного цикла («агент правит код → сам тестирует в Studio») существуют сторонние MCP-серверы, подключающие Claude Code напрямую к работающему редактору Roblox Studio через плагин-мост:

- Несколько независимых открытых реализаций такого «Roblox Studio MCP Server» позволяют агенту читать дерево инстансов, создавать/редактировать Script/LocalScript/ModuleScript, запускать playtest и читать вывод консоли прямо из Studio.
- Это сторонние (не от Anthropic и не от Roblox) инструменты с открытым кодом — до подключения стоит проверить репозиторий (звёзды, активность, дату последнего коммита) и то, что весь обмен идёт локально (localhost), не отправляя данные проекта на внешние сервера.
- Это опциональный, ускоряющий слой: без него Claude Code всё равно полноценно работает как редактор кода через Rojo-синхронизацию, просто плейтест придётся каждый раз запускать вручную в Studio.

Отдельно полезен обычный **GitHub MCP-сервер** (или встроенная git-интеграция) — для веток по фичам, PR-ревью силами `security-reviewer`-субагента перед мержем в основную ветку.

## 5. Skills (`SKILL.md`)

Skills в Claude Code — это переиспользуемые знания/чек-листы, которые агент подгружает при релевантной задаче (аналогично skills, которыми пользуется сам Claude в этом чате для docx/pptx/xlsx). Под этот проект имеет смысл завести собственные project-скиллы:

- **`roblox-luau-style`** — соглашения по стилю кода, `--!strict` типизация, паттерн модулей проекта (Init/публичный API), чтобы разные субагенты писали единообразный код.
- **`roblox-monetization-compliance`** — чек-лист из раздела 12 GDD (публикация odds, идемпотентность ProcessReceipt, ограничения PvP-потерь) — подключать перед любой работой над `MonetizationSystem`/`PvPRaidSystem`.
- **`economy-balance-template`** — шаблон таблиц/формул для `economy-balancer`, чтобы расчёты кривых апгрейдов были в одном формате и их можно было быстро проверять глазами.

В открытом доступе существует и сторонний универсальный skill для Roblox-разработки (роутер с большой справочной базой по Luau/монетизации/безопасности/производительности) — его можно подключить как отправную точку и адаптировать под свою архитектуру, вместо того чтобы писать всё с нуля; как и с MCP-серверами, это сторонний community-инструмент, а не официальный продукт Anthropic или Roblox — стоит просмотреть содержимое перед использованием.

## 6. Xlsx-навык для баланса экономики

В этом чате (Claude в Claude.ai/Claude Code с доступом к файлам) есть встроенный навык работы с Excel. Экономический баланс (кривые цен, RTP лутбоксов, прогноз ARPDAU) удобно вести как `.xlsx`-таблицу — это можно попросить сделать прямо здесь, отдельным запросом, до передачи чисел в `economy-balancer`-субагента как готовый `Config/*.luau`.

## 7. Рекомендуемый порядок настройки

1. Инициализировать git-репозиторий + Rojo project по структуре из ТЗ (раздел 3).
2. Завести `CLAUDE.md` с архитектурными принципами.
3. Создать субагентов `lua-systems-engineer`, `economy-balancer`, `security-reviewer` (остальные — по мере необходимости).
4. Реализовать MVP-фазу из ТЗ (раздел 11) силами `lua-systems-engineer`, без спешки с MCP-мостом в Studio — на этом этапе достаточно Rojo.
5. Подключить `roblox-monetization-compliance`-скилл и `security-reviewer` перед стартом работы над Beta-фазой (Хаос-ивент + монетизация).
6. Опционально — подключить MCP-мост в Studio, когда объём ручных плейтестов начнёт заметно тормозить итерации.
