# «Фабрика Снов» — Роадмап по сессиям Claude Code

Связанные документы: `01-GDD-Фабрика-Снов.md`, `02-ТЗ-Фабрика-Снов.md`, `03-Claude-Code-агенты-и-скиллы.md`.

Цель этого файла — разбить реализацию на задачи такого размера, чтобы каждая помещалась в один чат/сессию Claude Code без раздувания контекста, и явно сказать, где обязательно начинать новую сессию, а где можно продолжать текущую.

---

## 0. Правила экономии контекста (соблюдать во всех сессиях)

1. **Не вставлять GDD/ТЗ целиком.** В каждой сессии ссылаться на конкретный раздел («реализуй по разделу 5.3 из `02-ТЗ...`»), а не прикладывать весь файл — Claude Code сам прочитает файл из репозитория при необходимости, целиком грузить его в промпт не нужно.
2. **`CLAUDE.md` — только принципы, не весь GDD.** Он подгружается автоматически в начале каждой сессии, поэтому должен остаться компактным (архитектурные правила из раздела 2 ТЗ), иначе съедает контекст впустую в каждом чате.
3. **Новая сессия — при смене системы.** Переход от одной серверной системы к другой (например, FactorySystem → PetSystem) — повод начать новый чат, а не продолжать старый: история обсуждения FactorySystem не нужна для работы над петами и только засоряет контекст.
4. **Новая сессия — для плейтеста/багфикса.** Диалог «протестировали руками в Studio, нашли баги, правим» держать отдельно от диалога «пишем новую фичу с нуля» — это разные по характеру задачи с разным объёмом логов/скриншотов.
5. **Коммит после каждой сессии.** Каждая сессия должна заканчиваться рабочим коммитом. Тогда следующая сессия стартует не с пересказа «что мы уже сделали», а просто с чтения актуального кода репозитория.
6. **Субагент — не экономия контекста сама по себе.** Делегирование в субагента полезно внутри одной сессии (чтобы, например, ревью безопасности не засоряло основной диалог), но не заменяет начало нового чата при переходе к другому этапу.

## Как этим пользоваться на практике

- Каждая строка таблицы = отдельное новое сообщение/чат в Claude Code с формулировкой вида: «Сессия S4: реализуй FactorySystem по разделу 5.2 файла 02-ТЗ, контракты бери из `src/shared/Types.luau`».
- Если сессия внезапно разрослась (нашли смежный баг, потребовалась смежная правка) — не тащить это в ту же ветку разговора без необходимости: короткая правка ок, но если она перерастает в отдельную фичу — переносить в свою строку/сессию задним числом.
- Колонку «Зависит от» использовать как проверку перед стартом сессии: убедиться, что соответствующий код уже закоммичен, прежде чем начинать сессию, которая на него опирается.
